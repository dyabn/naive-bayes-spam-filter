# 基于朴素贝叶斯的垃圾邮件过滤与纠错系统汇报文稿

## 一 开场介绍

各位老师好，我汇报的项目是《基于朴素贝叶斯的垃圾邮件过滤与纠错系统》。

这个系统是一个教学型机器学习应用，主要目标不是接入真实邮箱服务器，而是通过模拟多个用户之间的邮件收发过程，展示垃圾邮件检测的完整流程。系统支持用户写邮件、发送邮件、查看收件箱、已发送和垃圾回收站，并且能够在邮件到达收件人时自动判断它是正常邮件还是垃圾邮件。

本项目的核心价值在于把抽象的贝叶斯公式变成一个可以操作和观察的系统。用户能够看到系统为什么把一封邮件判为垃圾邮件，也能够在系统误判时进行人工纠错。纠错后的数据会重新进入训练集，从而影响后续的贝叶斯概率计算。

## 二 项目完成了什么

本系统已经完成了以下功能。

第一，系统支持多个模拟用户。目前数据库中初始化了张三、李四、王五三个用户，用户之间可以互相发送邮件。

第二，系统实现了基本邮箱功能，包括写邮件、收件箱、已发送和垃圾回收站。发送一封邮件时，系统会为发件人保存一条已发送记录，同时为收件人生成一条接收记录。

第三，系统实现了两级垃圾邮件检测。第一级是固定关键词规则，第二级是伯努利朴素贝叶斯分类器。系统会先检查是否命中“优惠”“中奖”这类强规则词，如果命中，就直接判定为垃圾邮件。如果没有命中，才进入贝叶斯概率分类。

第四，系统支持分类解释。用户在界面中可以看到垃圾概率、正常概率、判定方式、判定原因，以及邮件中检测到的关键词特征。

第五，系统支持人工纠错。如果用户认为垃圾箱中的邮件不是垃圾邮件，可以点击“这不是垃圾邮件”；如果用户认为收件箱中的邮件是垃圾邮件，可以点击“标记为垃圾邮件”。系统会移动邮件位置，并把用户反馈写入训练数据。

第六，系统提供了 Tkinter 图形界面。界面采用三栏布局，左侧是导航，中间是邮件列表，右侧是邮件详情，方便课堂演示邮件流转和分类依据。

## 三 系统整体结构

项目采用分层设计，避免把所有逻辑都堆在一个文件中。

`database.py` 负责 SQLite 数据库，包括建表、初始化用户、初始化训练样本、保存邮件和保存反馈数据。

`bayes.py` 负责伯努利朴素贝叶斯算法，包括特征提取、先验概率计算、条件概率计算、拉普拉斯平滑、log 概率计算和最终概率归一化。

`mail_service.py` 负责业务逻辑，包括邮件分类、邮件发送、收件箱查询、已发送查询、垃圾箱查询和人工纠错。

`ui.py` 负责 Tkinter 图形界面，只做显示和接收用户操作，不重新写数据库逻辑，也不重新写贝叶斯算法。

`main.py` 是程序入口，负责初始化数据库并启动图形界面。

这样的结构对应了设计文档中的要求：界面层负责显示，业务层负责邮件流转，算法层负责机器学习分类，数据库层负责持久化。

## 四 Python 代码分析

这一部分我重点说明项目中的 Python 代码是如何组织的，以及各个文件之间是如何协作完成垃圾邮件检测的。

### 1 database.py 代码分析

`database.py` 是整个系统的数据持久化层，主要负责 SQLite 数据库相关操作。它不负责判断邮件是不是垃圾邮件，也不负责界面显示，只负责把数据保存好、查询出来。

文件开头定义了数据库路径：

```python
BASE_DIR = Path(__file__).resolve().parent
DATA_DIR = BASE_DIR / "data"
DEFAULT_DB_PATH = DATA_DIR / "mail.db"
```

这样程序运行时会默认把数据库文件保存在项目的 `data/mail.db` 中，便于管理，也避免把数据库散落到其他目录。

`get_connection()` 是数据库连接入口。它会创建数据库目录，打开 SQLite 连接，并设置：

```python
connection.row_factory = sqlite3.Row
connection.execute("PRAGMA foreign_keys = ON")
```

这样查询结果可以像字典一样通过字段名访问，例如 `row["username"]`，同时也启用了外键约束，保证邮件中的发件人和收件人必须是合法用户。

`create_tables()` 用来创建三张核心表：`users`、`emails` 和 `training_data`。其中 `emails` 表保存邮件的发送者、接收者、主题、正文、发送时间、概率、文件夹和判定原因；`training_data` 表保存训练文本、标签和样本来源。

`INITIAL_TRAINING_SAMPLES` 是默认训练集。系统第一次启动时，会通过 `seed_training_data()` 把这些样本写入数据库。现在训练集已经扩充到 52 条，正常和垃圾邮件数量保持平衡。

人工反馈相关的核心函数是：

```python
add_or_update_feedback_sample()
add_or_update_feedback_sample_with_connection()
```

这两个函数的作用是保存用户纠错产生的新训练样本。如果同一文本已经有 `user_feedback` 记录，就更新标签；如果没有，就插入新记录。这样可以避免用户反复点击导致同一封邮件被无限重复加入训练集。

邮件更新相关的函数是：

```python
update_email_folder_and_label()
```

它用于人工纠错时更新邮件所在文件夹和最终标签。例如用户把垃圾邮件改为正常邮件时，系统会把 `folder` 改成 `inbox`，把 `is_spam` 改成 `0`。

所以 `database.py` 的特点是：只管数据，不管算法，不管界面。

### 2 bayes.py 代码分析

`bayes.py` 是机器学习算法层，负责伯努利朴素贝叶斯分类。

首先定义了特征词：

```python
FEATURE_WORDS = [
    "限时", "领取", "点击", "链接",
    "免费", "现金", "礼品", "奖励",
    "恭喜", "促销", "优惠", "中奖",
]
```

这些词就是模型能够识别的特征。当前版本不是自动分词，而是使用固定特征词表，因此模型的学习和判断都围绕这 12 个词展开。

`extract_features(text)` 负责把文本转换成 0/1 特征。例如文本中出现“点击”，则 `"点击": 1`；没有出现则为 0。这体现了伯努利朴素贝叶斯的特点：只关心关键词是否出现，不关心出现次数。

`load_training_samples()` 从数据库的 `training_data` 表读取最新训练样本。这个设计很重要，因为它保证用户纠错后，下一次预测会自动使用新的训练数据。

`calculate_priors(samples)` 用来计算先验概率，也就是垃圾邮件和正常邮件在训练集中各自所占比例。代码中使用了平滑：

```python
(label_counts[label] + 1) / (total_count + len(LABELS))
```

这样即使训练数据较少，也不会出现过于极端的概率。

`calculate_conditional_probabilities(samples)` 用来计算条件概率，也就是某个关键词在某个类别中出现的概率。这里使用拉普拉斯平滑：

```python
(contains_word_count + 1) / (class_count + 2)
```

这样可以避免某个词在某一类中从未出现时概率为 0。

`_log_score()` 是实际计算分类分数的函数。因为朴素贝叶斯要把多个概率相乘，概率很小时容易出现数值下溢，所以代码使用 `math.log()`，把概率乘法转换成加法。

最后 `bayes_predict(text)` 返回：

```python
(spam_probability, normal_probability)
```

也就是垃圾概率和正常概率。需要注意的是，`bayes.py` 不执行“优惠/中奖直接判垃圾”的规则。这个规则放在业务层 `mail_service.py` 中，这样算法层和业务规则是分开的。

### 3 mail_service.py 代码分析

`mail_service.py` 是业务逻辑层，也是整个系统中连接数据库、算法和界面的核心文件。

`classify_mail(subject, content)` 是统一分类入口。它的流程是：

```text
主题 + 正文
    ↓
检查硬关键词 优惠/中奖
    ↓
命中则 rule 判定为垃圾
    ↓
未命中则调用 bayes_predict()
    ↓
根据 55% 阈值判断 inbox 或 trash
```

这个函数返回统一结构，包括：

```python
is_spam
spam_probability
normal_probability
classification_method
classification_reason
matched_keywords
```

这样界面层不需要重新判断邮件为什么是垃圾邮件，只需要展示业务层返回的结果。

`send_mail()` 实现邮件发送业务。它先调用 `classify_mail()` 得到分类结果，然后在数据库中插入两条邮件记录：

第一条是发件人的已发送记录：

```text
folder = sent
```

第二条是收件人的接收记录：

```text
folder = inbox 或 trash
```

这两条记录在同一个事务中完成，避免出现发件人显示发送成功但收件人没有收到的情况。

`get_inbox()`、`get_sent()`、`get_trash()` 分别查询收件箱、已发送和垃圾回收站。UI 点击左侧导航时，实际上就是调用这三个函数。

人工纠错由两个函数完成：

```python
mark_as_spam(email_id)
mark_as_normal(email_id)
```

`mark_as_spam()` 会把收件箱中的邮件移入垃圾回收站，并把文本作为垃圾样本写入训练数据。`mark_as_normal()` 会把垃圾回收站中的邮件移回收件箱，并把文本作为正常样本写入训练数据。

这里还有一个保护逻辑：如果邮件在 `sent` 文件夹中，系统不允许纠错。因为已发送记录属于发件人视角，不能因为收件人的纠错而修改发件人的已发送邮件。

### 4 ui.py 代码分析

`ui.py` 是界面层，使用 Tkinter 实现图形界面。

主类是：

class SpamMailApp:

它负责创建窗口、布局控件、响应用户点击。界面分为三部分：

中间是邮件列表，使用 `ttk.Treeview` 展示邮件的发件人或收件人、主题和时间。

右侧是邮件详情，显示正文、垃圾概率、正常概率、判定方式、判定原因和检测关键词。

所以 `ui.py` 的特点是：只负责显示和用户操作，不写 SQL，不写贝叶斯公式，也不写垃圾邮件判定逻辑。

## 五 数据库如何设计

系统使用 SQLite 作为本地数据库，主要有三张表。

第一张表是 `users`，用于保存模拟用户，包括用户 ID、用户名和密码。

第二张表是 `emails`，用于保存邮件记录。字段包括发件人、收件人、主题、正文、发送时间、垃圾概率、正常概率、是否为垃圾邮件、所在文件夹、判定方式和判定原因。

这里有一个重要设计：一次发送行为会产生两条邮件记录。第一条是发件人视角的 `sent` 记录，第二条是收件人视角的 `inbox` 或 `trash` 记录。这样张三发送邮件后，张三能在已发送中看到邮件；李四收到邮件后，也能在自己的收件箱或垃圾箱中看到邮件。

第三张表是 `training_data`，用于保存训练样本。每条样本包含邮件文本、标签和来源。标签 `1` 表示垃圾邮件，标签 `0` 表示正常邮件。来源可以是初始训练数据、人工整理的训练数据，或者用户反馈。

## 六 垃圾邮件识别是如何实现的

系统采用两级过滤策略。

第一级是固定关键词规则。系统会先把邮件主题和正文合并，然后检查是否包含“优惠”或“中奖”。如果包含，就直接判定为垃圾邮件，进入垃圾回收站。此时贝叶斯概率不参与最终判断，因此界面中垃圾概率和正常概率显示为横线。

第二级是伯努利朴素贝叶斯。如果邮件没有命中固定关键词规则，系统就把邮件交给贝叶斯分类器。

伯努利朴素贝叶斯关注的是关键词是否出现，而不是出现了几次。系统定义了 12 个特征词：

```text
限时 领取 点击 链接 免费 现金 礼品 奖励 恭喜 促销 优惠 中奖
```

对于每封邮件，系统会把这些词转换成 0 或 1。例如“限时领取礼品，请点击链接查看奖励”这封邮件中，“限时”“领取”“礼品”“点击”“链接”“奖励”都会被标记为 1，其他词标记为 0。

然后系统根据训练数据计算两类概率。

第一个是先验概率，也就是训练集中垃圾邮件和正常邮件各自占多少比例。

第二个是条件概率，也就是在某一类邮件中，某个关键词出现的概率。例如 `P(点击|垃圾)` 表示在垃圾邮件中出现“点击”的概率。

为了避免某个词从未出现导致概率变成 0，系统使用了拉普拉斯平滑：

```text
P(w|C) = (类别 C 中包含关键词 w 的邮件数 + 1) / (类别 C 邮件总数 + 2)
```

在实际计算时，系统没有直接把很多小概率相乘，而是使用 log 概率，把乘法变成加法，避免浮点数下溢。

最后，系统会把垃圾邮件和正常邮件两个 log 分数归一化，得到两个可显示的概率。当前阈值设置为 55%，当垃圾概率大于等于 55% 时，系统判定为垃圾邮件；否则判定为正常邮件。

## 七 系统如何训练

这个系统的训练方式和神经网络不同，不需要点击一个“训练按钮”，也不需要跑很多轮 epoch。

朴素贝叶斯的训练本质上是统计训练数据。只要 `training_data` 中的样本发生变化，下一次预测时系统重新读取训练数据，重新统计先验概率和条件概率，就相当于使用了新的模型。

系统有三类训练数据。

第一类是初始训练数据。项目最开始准备了 16 条训练样本，其中正常邮件 8 条，垃圾邮件 8 条，保证模型启动时不是空白状态。

第二类是人工整理的补充训练数据。为了让系统更好识别不包含“优惠”“中奖”的垃圾邮件，我补充了 36 条平衡训练样本，其中正常邮件 18 条，垃圾邮件 18 条。训练后默认训练集一共 52 条，正常邮件 26 条，垃圾邮件 26 条。

第三类是用户反馈训练数据。当用户点击“这不是垃圾邮件”或“标记为垃圾邮件”时，系统会把当前邮件的“主题 + 正文”作为训练文本，把用户纠正后的结果作为标签，保存到 `training_data` 中，并标记来源为 `user_feedback`。

为了避免用户连续点击同一个按钮导致同一封邮件被无限重复加入训练集，系统实现了“插入或更新”的逻辑。同一文本的用户反馈不会不断重复插入，而是更新已有反馈样本的标签。

## 八 训练效果如何

训练前，系统对大部分明显样本已经能正确识别，但对一类边界垃圾邮件识别不够好。例如：

```text
促销活动开始，请立即点击链接。
```

这封邮件不包含“优惠”和“中奖”，不会触发硬规则，只能交给贝叶斯模型。训练前它的垃圾概率是 21.94%，低于 55% 阈值，因此被误判为正常邮件。

我针对这类情况增加了促销类垃圾训练样本，例如：

```text
促销活动开始，请立即查看。
促销奖励正在发放，请立即点击。
促销礼品正在派送，请马上领取。
促销现金活动开启，请立即参与。
```

同时也补充了同等数量的正常邮件样本，避免模型整体偏向垃圾邮件。

训练后，同一封测试邮件：

```text
促销活动开始，请立即点击链接。
```

垃圾概率从 21.94% 提升到 74.82%，能够被正确判定为垃圾邮件。

在固定测试集中，训练前准确率为 90%，训练后准确率为 100%。这说明补充训练样本确实增强了模型对这类垃圾邮件的识别能力。

## 九 人工纠错如何影响模型

人工纠错是系统的反馈学习机制。

例如系统把一封邮件判为垃圾邮件，但用户认为它是正常邮件。用户点击“这不是垃圾邮件”后，系统会做三件事。

第一，把这封邮件从垃圾回收站移回收件箱。

第二，把邮件的 `is_spam` 改为 0。

第三，把邮件文本作为正常样本写入训练数据。

之后系统再次预测类似邮件时，相关关键词在正常邮件中的概率会提高，因此垃圾概率通常会下降。

反过来，如果用户把收件箱中的邮件标记为垃圾邮件，系统会把邮件移入垃圾回收站，并把邮件文本作为垃圾样本写入训练数据。后续类似邮件的垃圾概率通常会上升。

需要说明的是，人工反馈只影响贝叶斯模型，不会取消固定关键词规则。例如一封邮件包含“优惠”，即使用户把当前这封邮件恢复为正常，下一次再收到同样包含“优惠”的邮件时，系统仍然会优先命中固定规则，把它放入垃圾回收站。这是设计文档中明确规定的规则优先级。

## 十二 项目总结

本项目完成了一个可运行、可演示、可纠错、可训练的垃圾邮件检测系统。

从实现上看，系统使用 SQLite 保存用户、邮件和训练数据；使用伯努利朴素贝叶斯完成概率分类；使用固定关键词规则处理明确垃圾词；使用 Tkinter 提供图形化操作界面。

从机器学习角度看，系统不是简单依赖固定规则，而是会根据训练数据统计概率。当补充训练样本或用户反馈发生变化后，后续预测概率也会变化，体现了反馈学习过程。

从演示角度看，系统能够清楚展示邮件如何从发送方流转到接收方，如何进入收件箱或垃圾回收站，为什么被判为垃圾邮件，以及用户纠错如何影响后续判断。

因此，这个项目基本达到了设计文档中的目标：把抽象的朴素贝叶斯算法转化为一个可以操作、可以观察、可以讲解的垃圾邮件过滤与纠错系统。
